# 函数

## 1. 写之前按顺序判断，停在第一个成立的

1. 推测出来的需求（"以后可能要"）→ 不写
2. 项目里已有同样职责的函数 → 复用
3. 标准库或已装依赖能做 → 直接用
4. 一行可读的表达式能写清 → 不包函数
5. 以上都不成立 → 写最少量的实现

限制：

- 不为少写代码牺牲性能（该有的索引、向量化照写）
- 校验、错误处理、类型注解一项不减
- 封装要有 2 个以上调用方或一段独立逻辑，否则内联

## 2. 函数还是类（先看全项目，再看单个文件）

- 全项目有多个同类实体（如 8 个电源），字段和操作步骤相同：每个实体一个类、一个模块文件；共同字段和步骤放基类，子类只写差异。不按实体复制多份函数，也不用实体编号参数区分
- 没有这种结构时默认用函数，拿不准就不封装。以下情况才封装成类：
  - 同一批参数在 3 处以上反复传递
  - 数据天然是一个实体（一类设备、一张表）→ 用数据类装数据（见 class.md）
  - 需要跨多次调用保持状态，或初始化一次多处使用
- 单个脚本内：

| 情形 | 写法 |
| :--- | :--- |
| 流程短且线性 | 模块级函数 + `main()` 入口 |
| 多个操作围绕同一批数据 | 数据放数据类，操作仍是函数 |
| 操作和状态绑定，是一个实体 | 封装成类 |

## 3. docstring

- 首行一句话说清做什么
- `Args:` 每个参数写 `名字 (类型): 中文含义`
- `Returns:` 写 `类型: 中文含义`；没有返回值写 `Returns: None`

```python
def weighted_sum(w: np.ndarray, X: np.ndarray) -> np.ndarray:
    """按权重对矩阵各行加权求和。

    Args:
        w (np.ndarray): 权重向量 (N,)。
        X (np.ndarray): 数据矩阵 (N, T)。

    Returns:
        np.ndarray: 各时段加权和 (T,)。
    """
```

## 4. 签名

- 同类函数签名一致，用不到的参数直接忽略，不开特例、不加第二个变体
- 默认参数只用于向后兼容的新增参数
