# 算法模块重写：结构模板与对算验证（new_energy/wind.py，2026-10-29）

任务：风电算法从旧 WindPowerModel 从规格重写。适用：把一个算法/模型模块整体重写；
只改数据加载或业务包装不适用本文件。防搬运自查见 reference/rewrite.md，此处只写算法重写多出的三类规则。

## 结构模板（先定结构再写逻辑）

- 顶层模型类：`__init__(config)` 组装各步子模块，`forward` 按数据流顺序执行（`__call__ = forward`）
- 每个子模块只公开两个方法：`__init__(config)` + `__call__(data)`；`__call__` 即该模块 forward、置于类的最后，逻辑直接写其中，不另拆小函数
- 多步链（如校准链）各步收为本类私有方法，`__call__` 顺序调用；跨子模块共用的查表工具留模块级
- 魔法数（阈值、分块大小、惩罚系数）提为模块级具名常数
- 反面形状（旧码）：一个行为一个类层层包装、状态经属性层层传递，步骤被类边界切碎，数据流读不出来

## 数据表示（从行为清单推导，不从旧码继承）

- 核心序列装箱为规整 ndarray（行=样本、列=位置），月/时等派生量由位置查表得出，不逐点重算
- 重型库只留在门口（对齐/解析）与出口（装箱为 Series、结果封装），中间计算全 ndarray
- 选什么表示属于行为清单的一部分：先写清输入什么形状、每步进出什么形状，再选容器

## 对算验证（重写期间行为冻结）

- 冻结项：随机种子与抽样顺序、公式表达式、输出列集；判据（逐位/容差）按 skill verify-results
- 与旧实现同输入对算，目标逐位一致；不一致按数据流逐级二分——逐中间量（特征、事件、标准、参数、各校准步）对算，定位到出偏差的步
- 旧 fixture 未覆盖的路径（如评估分支）造合成数据对算补
- 结构精化分步合入，每合一步对算一次仍逐位一致，再进下一步
