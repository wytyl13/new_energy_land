# 规划项目

## 顺序（不跳步）

1. **需求确认**：做什么、不做什么，写进 DESIGN〔草案〕，用户确认后改为〔已确认〕；需求不清不动手
2. **宏观方案**：宏观步骤和每步目的，写进 PLAN「步骤」（P1、P2…），用户确认后再细化
3. **细化**：展开成可执行步骤（P1.1、P1.2…），写进 PLAN「步骤」
4. **执行**：DESIGN 先于代码，涉及的 DESIGN 节写好再写代码
5. **验证**：每个细化步骤做完按 `verify-results` 核对，结果写进 PLAN「步骤」的验证结果列，通过才进入下一步

## 执行方式（细化开始前由用户选）

| 方式 | 做法 | 何时用 |
| :--- | :--- | :--- |
| 滚动式（默认） | 细化一个宏观步骤 → 执行 → 验证通过 → 再细化下一个 | 需求或技术不确定 |
| 全局式 | 一次细化全部宏观步骤，确认后逐个执行验证 | 范围明确、改动模式重复 |

- 用户没选时用滚动式，并说明理由
- 全局式确认后连续执行，只在验证失败或要偏离方案时停下

## 确认点

只在三处停下等用户确认：需求、宏观方案、细化方案（滚动式逐个，全局式一次）。
执行中的小改动不逐个确认，结果如实汇报。
