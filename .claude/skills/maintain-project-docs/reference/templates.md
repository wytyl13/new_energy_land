# 模板

## PLAN.md

```markdown
# 计划与进度

## 当前状态
- 正在做：…
- 下一步：…
- 阻塞：无

## 待决定
- Q-01 问题…：A / B，待定（定后写进 DECISIONS.md，这里改成"→ D-xx"）

## 步骤
| 编号 | 步骤 | 状态 | 验证结果 |
|---|---|---|---|
| P1 | 宏观步骤 | 未开始 | |
| P1.1 | 细化步骤 | 未开始 | |

## 待办
- [ ] …
```

- 状态用文字：未开始 / 进行中 / 已完成 / 搁置
- 提交信息以步骤编号开头（如 `P1.1: …`）

## DECISIONS.md

```markdown
# 决策记录

> 只增不删；被取代的决策在行尾注明"被 D-xx 取代"。

- D-01（2026-10-26）接口格式单独建 API.md。理由：DESIGN 只写算法。依据：用户选 B
```

- 只记两类：影响设计的方案选择；改〔已确认〕或冻结内容
- 不记文件改动（看 git），不记进度（看 PLAN）

## README.md

只写怎么用，依次：

1. **简介**：一段话，做什么、输入、输出
2. **Quick Start**：环境、安装、运行、服务启动（如有）、git 工作流；命令块可直接复制执行
3. **使用说明**：参数、输入文件放哪、输出文件在哪
4. **文档导航**：DESIGN、PLAN、DECISIONS、API 各一行说明

## API.md（有服务层才建）

```markdown
# <项目名> 接口

> 接口简介：属于什么项目、做什么、端口与实现位置、耗时特点，两三行让人一眼看清楚。
> 改格式前先在 DECISIONS.md 记一条；同步改测试里的格式断言。

## <接口名> <METHOD> /api/...

<接口描述：这个接口干什么；不同传参数据体量的运行时长大概多少>

传参：
（JSON 示例：嵌套对象逐行展开，不压一行；每个字段行尾写 // 必填/可选（默认值），用途）

返回：
（同样写法）
```

- 行尾注释就是字段说明，不再另附字段表；每个字段（含嵌套层）都写必填/可选和用途，传参和返回同样要求，同构接口的差异字段也不省略
- 运行时长写实测值，注明对应的数据体量（如"全省 18 地市约 220s、单地市约 13s"）
