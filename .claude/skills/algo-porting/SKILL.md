# 代码移植与重构规则

边界：同时管"旧代码（含其它语言）翻译成 Python"和
"已有 Python 代码的架构重构"，两者流程相同。

## 1. 移植模式（先确认用哪种）

| 模式 | 何时用 | 做法 |
| :--- | :--- | :--- |
| **最优移植（默认）** | 用户未特别说明 | 按目标语言惯用结构重写，行为与旧代码一致即可；不逐行对照 |
| **一比一复刻** | 用户明确要求"一比一对照复刻移植" | 一行对一行：旧代码一行 = 新代码一行为目标；拆行/合并必须注释对照行号（如 `# L123`）；禁止顺手"改进"逻辑、变量名、结构 |

- 两种模式下都禁止顺手"优化"行为；优化另开任务。

## 2. 前置条件

- **算法流程表述先行**：重构/移植模型项目，动代码前先把原始项目
  算法流程写入 `DESIGN.md`（原始项目部分）；重构收口后在重构部分
  并列再写一份，两版对照。结构与表述模板见 `design-doc`
  （重构类项目的表述结构），多余内容不加。
- **重构工作区独立**：重构产物放项目根下独立目录（如 `refactor/`），
  按子项目分子目录、互不打扰，公共脚本进 `common/`（出现第一个公共
  脚本前保持空）；原始代码零改动、留作参照。目录/包/文件名用英文，
  且按子项目主题命名（如 `load_model`），不用序号泛称（如 `topic1`）
  （命名规则见 `project-bootstrap`），交流与文档用中文。
- 移植前先明确权威顺序：理论文档 > 旧语言源码 > 推断；
  旧源码可能有错，发现疑似错误上报，不静默修正。
- 未验证就翻译的模块记为待办记录，回头按文档修正。

## 3. 旧代码注释处理（默认保留，可按要求省略）

- 默认：旧代码注释原样翻译带入，不删不减。
- 用户明确说可以省略时才省略。

## 4. 基准先行（重构/移植第一步，不可跳过）

- 动第一行代码**之前**，用当前代码（或旧语言代码）跑出基准并
  保存到文件：全量输出文件 + 逐文件校验和（md5）。
- 基准一旦建立即冻结；期间发现旧代码疑似 bug，记录上报，
  **不在迁移分支顺手修**（先保持结果一致，修复另开任务）。

## 5. 冻结口径

- 迁移不改行为，只改结构。以下口径冻结：
  - 变量/约束规模与建序；
  - 输出文件的列集、行序、精度；
  - 对外接口与键名（见 `code-decoupling`）。

## 6. 小步迁移与回归判据

- 按模块小步迁移：一次只动一个模块，改完 → 与基准比对 →
  通过 → 提交 → 下一个；每步可独立回滚（流程见 `process-workflow`）。
- 一致性判据（两级，事先声明用哪级，细则见 `process-verify`）：
  - **一比一复刻 / 纯重构**：逐位一致（文件 md5 相同）；
  - **最优移植**：容差一致（总量相对偏差、逐元素相对偏差
    双指标都过才算过）。
- 输出文件若为比对基准件，列集冻结，格式对齐旧版。
- 全部模块迁完跑一次全量回归（含代表性大算例）再收口。
