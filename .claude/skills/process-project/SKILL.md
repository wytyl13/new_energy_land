# 项目编写与重构流程（项目级）

边界：只管项目级的阶段划分与推进方式。单次改代码的流程归 `process-workflow`，
核对判据归 `process-verify`，文档同步归 `process-doc-sync`。

## 1. 顺序固定（不许跳步）

1. **需求确认**：与用户确认做什么、不做什么；需求不清不动手。
2. **宏观方案**：列出宏观步骤（大方向 + 每步目的），经用户确认后才进入细化。
3. **细化**：把宏观步骤展开成可执行的细化步骤。
4. **执行**：按细化步骤改代码、写文件。
5. **验证**：每个细化步骤执行完必须验证（判据见 `process-verify`），
   通过才进入下一步。

## 2. 执行模式（细化开始前选定，二选一）

| 模式 | 做法 | 何时用 |
| :--- | :--- | :--- |
| 滚动式（默认） | 定好宏观方向与目的后逐个细化：细化第一个宏观步骤→执行→验证通过→再细化下一个 | 需求或技术不确定、边做边看 |
| 全局式 | 一次性制定全部宏观步骤的细化方案，确认后逐个执行验证 | 范围明确、改动模式重复 |

- 模式由用户选定；不选时默认滚动式并说明理由。
- 全局式确认后连续执行，只在验证失败或偏离计划时回来找用户。

## 3. 确认点（少而关键）

只在三处停下等用户确认：需求、宏观方案、细化方案（滚动式逐个 / 全局式一次）。
执行中的小改动不再逐个确认，执行结果如实汇报。
