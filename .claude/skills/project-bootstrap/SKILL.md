# 新建项目规则（从 0 开始）

边界：只管项目冷启动。日常改代码流程归 `process-workflow`。

## 1. 先设计后建目录

- 动手前先出：项目定位（纯算法 / 算法+服务 / …）、分层图、
  模块列表，经用户确认再建目录。
- 目录结构按 `code-decoupling` 的分层落地，从第一天就单向依赖，
  不留"以后再理"。

## 2. 目录最小集

- 目录 / 包 / 模块 / 文件名一律**英文**命名：交流与文档用中文，
  但创建工程产物（目录、包、模块、脚本文件）不用中文命名。

```
<project>/
  README.md          定位、环境、执行命令、输出说明
  requirements.txt / environment.yml
  src/ 或 <包名>/    入口层 → 输入层 → 单元层 → 系统层 → 组装层 → 结果层
  data/              输入数据（不入 git 则写 .gitignore + 说明）
  tests/ 或 自检脚本  最小可运行检查
```

## 3. 环境规则

- 环境名单独成文件，第一天就锁定版本。
- Python 环境命名与项目对应，执行命令写进 README。

## 4. 第一条可运行路径

- 冷启动的完成标准：一条命令能跑通
  "读一份最小输入 → 出一份最小输出"的端到端路径，
  之后再按模块充实（配合 `algo-data` 的校验规则）。

## 5. git 规则

- 初始提交只含目录结构与首批代码；数据/密钥/临时文件进 .gitignore。
- 提交信息说清"做了什么"，一步一提交。
