# 模块分层

边界：只管分层与依赖方向的通用原则，不限定具体领域。本项目的具体分层写在 DESIGN「模块对应」。

## 1. 分层总原则

- 依赖**单向**，禁止反向 import；画得出分层图的才允许加依赖。
- 典型分层（自上而下，按项目实际裁剪）：

```
入口层（main / run）      对外唯一出口
  ↓
输入层（reader）          系统公共输入
  ↓
单元层（units/*）         每个计算单元自包含，互不知道彼此
  ↓
系统层（context）         跨单元耦合与全局约束，只发生在这里
  ↓
组装层（assemble）        循环组装 → 目标 → 调用底层库
  ↓
结果层（solution/plot/export）  纯取值与输出
```

## 2. 各层规则

- 单元不知道组装层存在；系统层不改单元内部。
- 耦合逻辑只写在系统层，**不把耦合塞回单元**。
- 全项目只有一个文件调底层库（外部引擎/第三方工具）并设其参数。

## 3. 入口规则

- 算法包对外**唯一显式入口**：外部只 import 这一个文件，
  构造配置对象后调用；禁止 sys.path 直插、
  禁止外部直接改写包内模块属性。

## 4. 顺序规则

- 遍历顺序、加法顺序、列集影响结果比对，不随手改；新增项按文档核对插入位置，不随手 append。
