# 移植与重构旧代码

## 1. 移植方式（先确认用哪种）

| 方式 | 何时用 | 做法 |
| :--- | :--- | :--- |
| 最优移植（默认） | 用户没特别说明 | 按 Python 惯用写法重写，行为和旧代码一致，不逐行对照 |
| 一比一复刻 | 用户明确要求 | 旧代码一行对新代码一行；拆行或合并须注释对照行号（如 `# L123`）；不改逻辑、变量名、结构 |

- 两种方式都不顺手改行为；要改另开任务

## 2. 动代码前

- 先在 DESIGN「模块对应」写原项目模块、新项目模块两列（粒度到文件），算法设计各节按 `maintain-project-docs` 写好，用户确认后再动代码
- 重构产物放项目根下独立目录（如 `refactor/`），按子项目分子目录；公共脚本放 `common/`，出现第一个公共脚本前保持空；原代码不改，留作对照
- 目录、包、文件名用英文，按主题命名（如 `load_model`），不用 `topic1` 这类序号
- 旧源码可能有错：发现疑似错误上报，不静默修正，也不在迁移中顺手修
- 没验证就翻译的模块记进 PLAN「待办」

## 3. 旧代码注释

- 默认原样翻译带入，不删不减；用户明确说可以省略才省略

## 4. 迁移步骤

1. 动第一行代码前建基准（方法见 `verify-results`），建好后不再改
2. 只改结构不改行为：变量和约束的规模与建立顺序、输出文件的列集行序精度、对外接口键名都保持不变
3. 一次迁一个模块：改完 → 和基准比对 → 通过 → 提交 → 下一个
4. 判据：一比一复刻和纯重构用逐位一致；最优移植用容差一致（见 `verify-results`）
5. 全部迁完跑一次全量回归（含有代表性的大算例）再收尾
