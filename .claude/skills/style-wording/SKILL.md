# 用词与表述规范

边界：只管"文字怎么写"。代码结构归 `code-function` / `code-class`，
文档同步时机归 `process-doc-sync`。

## 1. 禁用词与替换

以下词在注释、README、文档、表述中一律不用，按右列替换：

| 禁用            | 替换为             |
| :-------------- | :----------------- |
| 纪律            | 规则               |
| 对拍            | 结果比对           |
| 落盘            | 保存到文件         |
| 合同            | 固定不变的对外约定 |
| 骨架            | 目录结构           |
| 债务 / 债务清单 | 待办记录           |
| 节奏            | 顺序 / 步骤        |
| 清单            | 列表               |
| 账本            | 记录               |
| 编排            | 组织               |

## 2. 表述原则

- 平实的技术语言：直接说做什么、是什么，不用比喻。
- 不堆修饰词：删掉"严格地""本质上""核心的""强大的"这类
  不改变信息量的形容与副词。
- 一句话只说一件事；能用表格或短列表就不用长段落。
- README 只写：项目定位、环境、执行命令、输出说明，不写营销式介绍。

## 3. 适用范围

- 代码注释、docstring、README、设计文档、commit 信息、对话表述，
  以及本 skills 目录下所有规则文件自身。
- 发现旧文件里有禁用词，随本次改动顺手修正，不专门全局清理。
