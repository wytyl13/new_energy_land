# 管理 skills

## 1. 新规则放哪（按序判断，停在第一个成立的）

1. 每次都要遵守 → CLAUDE.md
2. 只属于本项目的事实或设计 → DESIGN.md / API.md
3. 能写出 3 条和现有 skill 都不重叠的触发语句，且用户会单独要求做这件事 → 新建 skill
4. 其他情况 → 扩展进触发语句重叠的那个 skill：
   - 是同一流程的变体（换语言、换格式）→ 加一个 reference 文件，SKILL.md 的"按任务读"表加一行
   - 总是作为某个任务的一步出现 → 写进那个任务的 skill 正文

## 2. 拆分与合并的信号

- 拆分：description 里用"或"连接了几件不相关的事；每次触发时超过一半内容和当前任务无关；经常误触发或漏触发
- 合并：两个 skill 的 description 放在一起分不清该用哪个；总是同时触发；内容大量重复

## 3. 写法

- name：动词 + 对象，英文小写，单词之间用连字符，不加领域前缀
- description：做什么 + 用户会怎么说，必要时加一句不适用的情况
- 正文只写模型不知道的东西：本项目的约定、格式、踩过的坑，不写常识
- SKILL.md 放概要和"按任务读对应文件"表，细节放 reference/，只分一层
- 引用别的 skill 只写 skill 名；不写具体项目的路径、函数名、定稿格式

## 4. 登记与测试

- 新增或修改 skill 后，在 .claude/evals/triggers.md 补至少 3 条应命中、1 条不应命中的语句，逐条检查
- 新增、修改都须用户批准；提交信息写明用户原话依据
