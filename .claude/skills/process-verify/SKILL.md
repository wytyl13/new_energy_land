# 验证规则

边界：只管"改完/跑完之后怎么核对"。文档同步归 `process-doc-sync`。

## 1. 四项核对（每次运行后，进日志再谈结论）

| # | 核对项 | 含义 |
| :--- | :--- | :--- |
| 1 | 规模 | 变量数/数据量与设计一致 |
| 2 | 约束/规则规模 | 约束行数/规则条数与设计一致 |
| 3 | 执行状态 | 正常完成，无静默降级 |
| 4 | 结果数值 | 目标值/关键数值在合理范围 |

- **结果没核对 = 结论不成立**。

## 2. 基准比对（改代码前先建）

- 重构/优化任何已有代码前，先用**当前代码**跑出基准结果并保存到文件
  （逐时段数据 + 汇总指标 + 文件校验和）。
- 改完与基准比对：比对口径（列集、精度、判据）事先写明，
  不许比对失败后临时放宽判据。

## 3. 回归判据

- 一致性分两级，事先声明用哪级：
  - **逐位一致**：文件级 md5 / 逐字节相同（重构类改动用）。
  - **容差一致**：相对偏差 ≤ 事先约定的容差，且两个指标都过才算过
    （如：总量相对偏差、逐元素相对偏差）。
- 一个指标过了另一个没过 = 不一致，上报不自行决定。

## 4. 数值安全

- 不定式（0/0、Inf-Inf）、不确定的数值一律显式处理，
  禁止裸 NaN 进模型与计算（读取侧拦截见 `algo-data`）。
- 浮点比较用容差，不用 `==`。
- 默认容差参考：总量相对偏差 ≤ 1e-6，逐元素相对偏差 ≤ 1e-4；
  任务另有约定时以约定为准。边界上浮动的结果上报，不四舍五入凑过。
