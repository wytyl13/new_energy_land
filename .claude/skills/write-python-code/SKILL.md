# 写 Python 代码

## 共同规则

- 类型注解必写
- 一个函数或类只做一件事；取数、计算、保存文件不放在一起
- 全项目同一职责只有一个出口（如只有一处调底层库），其他地方复用，不各自实现
- 从输入/输出直接推导最简实现，代码简洁明了；产出前自查：同一表达式构造超过 1 次即合并、同一数据分组/遍历超过 1 次即合并（新建与重写都适用）
- 行为写对后再退一步看表达：条件过滤能换成集合交并的，换成集合当起点（如窗口过滤条件 → `set(range(...)).intersection(...)`），过滤条件整个消掉（用户确认 2026-10-29）
- 任何函数内部步骤都用编号注释罗列（`# 1.` `# 2.` …），一步一行说清做什么；单步免标
- 已扫描/已算出的中间结果直接复用（如一次扫目录同时得到年份与路径），不重复遍历同一数据
- 共享的底层函数放被依赖的模块，不因某个调用方搬动位置，不让依赖方向反向

## 重写/重新设计任务（用户确认 2026-10-29）

- 先从需求列行为清单（输入、输出、报错），再从清单直接推导最简实现；旧代码只用于核对行为没漏，不作为实现模板
- 搬运自查：旧代码带来的每个函数、分支、中间变量单独问"删掉它行为不变吗"，不变就删——不给它写 docstring、不起名字；行为是"恰好 N 个"这类单一约束时一个条件表达（如 `len(files) != 1`），不照抄旧的多分支
- 反面/正面对照案例（自查标准对新建代码同样适用）：reference/rewrite.md

## 紧凑写法（用户确认 2026-10-28）

- 校验内联在使用处，不建一次性包装函数（fail/string/check_* 之类）；同一逻辑 3 处以上重复才提函数；单一调用方的辅助函数（含计数、小取数）直接内联
- 分支少直接 if/else 写在使用处，不做表驱动配置（先建 KIND_OPTIONS 这类表再查表取差异项的写法）
- 校验下沉到数据类 `__post_init__`（构造即校验）；中间层只透传原始值，不重复查、不提前强转
- 取值一行：`payload.get(key, default)` 填默认值；`x = a if cond else b` 三元
- 简单守卫单行：`if not ok: raise ValueError("...")`

```python
payload = source if isinstance(source, dict) else json.loads(Path(source).read_text("utf-8"))
if not isinstance(payload, dict): raise ValueError("配置文件根必须是 JSON 对象")
```
