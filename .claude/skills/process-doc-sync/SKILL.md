# 文档同步规则

核心原则：**代码改了文档不同步 = 改动未完成**。

边界：只管"事实描述的同步"。核对结果归 `process-verify`，
文字用词规范归 `style-wording`。

## 1. 三方一致性

- 代码、README、规则文档（skills）三处描述同一事实；
  冲突时**以代码为准**，同步修其余两方。
- 不只改一处留两处旧描述。

## 2. 触发映射（改了什么 → 必须同步哪里）

- 每个项目维护一张映射表：代码改动类型 → 文档同步位置。
- 改前先查映射，改完逐项核对映射表是否全部同步。

## 3. 引用规则

- 正文引用代码位置用统一格式（编号引用或路径+行号），
  不裸写、不错链。
- 编号只增不复用不删；行号变了同步改映射表。

## 4. 格式与步骤

- 沿用文档原有格式（表格对齐、章节顺序、标点），不顺手美化。
- 大改分小步：先同步表格行，再补链接，最后核对锚点可跳转。
- 标注"冻结/比对基准"的部分，改动必须注明比对影响。
